## 1. Контекст и мотивация

System One (S1) — класс легковесных локальных моделей, которые не занимаются авторегрессионной генерацией длинного текста, а за один прямой проход (forward pass) вычисляют калиброванные типизированные решения:
- **`Choice`**: выбор одного из $N$ дискретных вариантов (2–26 опций);
- **`Score`**: оценка по дискретной шкале уровней (2–8 уровней);
- **`Noul`**: калиброванная вероятность истинности бинарного утверждения $P(\text{true}) \in [0.0, 1.0]$.

В текущей архитектуре Omnes Agent (`backend/`) решения о маршрутизации, фильтрации и пригодности контекста либо возложены на дорогостоящие сетевые вызовы тяжелых LLM, либо выполняются через хрупкие эвристики (поиск подстрок, регулярные выражения, слепое усечение очереди).

### Задачи System One в Omnes Agent:
1. **Канальная интент-классификация**: ликвидация сетевого обращения к LLM на каждый входящий кадр в групповых чатах (`classify_channel_reply_intent`).
2. **Семантическая компакция контекста (fast-jev-compaction)**: замена слепого вытеснения старых ходов (`history_trim.rs`) на сохранение критически важных для цели витков диалога.
3. **Реранжирование памяти перед инжектом**: семантическая фильтрация воспоминаний (`memory_inject.rs`) вопросом Noul «отвечает ли запись на запрос?».
4. **Динамический отбор инструментов**: замена англоязычного словаря ключевых слов (`context_analyzer.rs`) на мультиязычный классификатор категорий инструментов.
5. **Семантическая маршрутизация моделей**: классификация сложности пользовательского намерения (`classifier.rs` + `model_router.rs`).

## 3. To-Be архитектура

### 3.1 Выбор расположения модуля: крейт `omnesagent-s1`
Архитектурное решение: создание отдельного крейта воркспейса `crates/omnesagent-s1`.
- **Изоляция зависимостей**: зависимости `candle-core`, `candle-nn`, `candle-transformers`, `tokenizers`, `hf-hub` изолируются внутри крейта под опциональной фичей `candle` (по аналогии с `omnesagent-kag`). Крейт `omnesagent-compression` остается легким (zero-ML), а `omnesagent-runtime` не раздувается.
- **Предотвращение циклов**: `omnesagent-s1` не зависит от `omnesagent-runtime`, что позволяет подключать его в `runtime`, `compression`, `channels` и `eval`.
- **Контракт интерфейса**: единый типаж `SystemOne` + легковесный детерминированный `FakeSystemOne` для мгновенных юнит-тестов без подгрузки 421M параметров.

## 4. Функциональные требования (FR)

### FR-1: Ядро и контракт `omnesagent-s1`
- **FR-1.1**: Определить типы вопросов `Question`:
  - `Choice { id: String, prompt: String, options: Vec<String> }` (от 2 до 26 вариантов);
  - `Score { id: String, prompt: String, levels: u8 }` (от 2 до 8 уровней);
  - `Noul { id: String, prompt: String }` (бинарная калиброванная вероятность).
- **FR-1.2**: Определить типы ответов `Answer`:
  - `Choice { selected_index: usize, selected_value: String, probabilities: Vec<f32>, confidence: f32 }`;
  - `Score { selected_level: u8, probabilities: Vec<f32>, confidence: f32 }`;
  - `Noul { probability: f32, is_true: bool }`.
- **FR-1.3**: Реализовать трейт `SystemOne: Send + Sync`:
  ```rust
  #[async_trait::async_trait]
  pub trait SystemOne: Send + Sync {
      async fn decide(&self, state: &str, questions: &[Question]) -> anyhow::Result<Vec<Answer>>;
      fn model_id(&self) -> &str;
      fn is_available(&self) -> bool;
  }
  ```
- **FR-1.4**: Реализовать детерминированный `FakeSystemOne` с возможностью программирования ответов и дефолтной псевдослучайной хэш-генерацией для тестов без загрузки весов.
- **FR-1.5**: Реализовать фабрику провайдеров `create_system_one(config: &SystemOneConfig) -> Arc<dyn SystemOne>`.

### FR-2: Драйвер инференса Laya на Candle (`CandleLayaProvider`)
- **FR-2.1**: Использовать существующий в дереве воркспейса `candle_transformers::models::modernbert::ModernBert` (версия 0.8). Никаких внешних питоновских процессов или HTTP-серверов.
- **FR-2.2**: Загрузка весов: `safetensors` энкодера ModernBERT + веса decision head из локального пути `OMNESAGENT_S1_PATH` либо через `hf-hub` из репозитория `convaiinnovations/laya`.
- **FR-2.3**: Асинхронность и блокировки: инференс модели выполняется синхронно внутри `tokio::task::spawn_blocking`, исключая блокировку пула воркеров Tokio.
- **FR-2.4**: Ограничение длины входа: при превышении `OMNESAGENT_S1_MAX_TOKENS` (дефолт: 512 токенов) применять сохранение заголовка и хвоста (head 256 + tail 256) с отбрасыванием середины.
- **FR-2.5**: Поддержка квантования: опциональная загрузка квантованных весов (q8/int8) для сокращения потребления RAM.

### FR-3: Интеграция P1 — Канальная интент-классификация (`omnesagent-channels`)
- **FR-3.1**: В `omnesagent-channels/src/orchestrator/mod.rs` при активном флаге `OMNESAGENT_S1_CHANNEL_INTENT=1`:
  - Состояние формируется из последних 3 реплик чата.
  - Формируется вопрос `Choice` с вариантами: `["REPLY", "NO_REPLY_INFO", "NO_REPLY_REFUSE"]`.
  - При `confidence >= 0.75` результат классификации применяется **без сетевого вызова к LLM**.
- **FR-3.2**: При ошибке инференса, таймауте (>150 мс) или флаге `OFF` управление прозрачно передается существующей функции `classify_channel_reply_intent` (fallback на сетевой LLM).

### FR-4: Интеграция P2 — Семантическая компакция контекста (`omnesagent-runtime`)
- **FR-4.1**: В `omnesagent-runtime/src/agent/history_trim.rs` при флаге `OMNESAGENT_S1_COMPACTION=1`:
  - Вместо последовательного срезания ходов $0, 1, 2...$ каждому кандидату на удаление выставляется оценка через вопрос `Score(levels=5)`: «Оцените важность этого витка для текущей цели: {user_goal}».
  - Первыми удаляются витки с наименьшим баллом (1 и 2). Витки с баллом 4 и 5 сохраняются до исчерпания всех низкоранговых.
- **FR-4.2**: Интеграция с `TokenCompressor` (`omnesagent-compression`): при сжатии вывода инструментов с `Score <= 2` применяется максимальное сжатие `SmartCrusher`, при `Score >= 4` сохраняется полный вывод.

### FR-5: Интеграция P3 — Семантический реранк памяти (`omnesagent-runtime`)
- **FR-5.1**: В `omnesagent-runtime/src/agent/memory_inject.rs` при флаге `OMNESAGENT_S1_MEMORY_RERANK=1`:
  - Пул кандидатов памяти (топ-10 после базового поиска) прогоняется через пакет вопросов `Noul`: «Содержит ли эта запись ответ на текущий запрос?».
  - Записи сортируются по вероятности $P(\text{true})$. Записи с $P < 0.40$ исключаются из инжекта в системный промпт (при условии сохранения минимум 1 записи).

### FR-6: Интеграция P4 — Мультиязычный анализ контекста тулов (`context_analyzer.rs`)
- **FR-6.1**: В `omnesagent-runtime/src/agent/context_analyzer.rs` при флаге `OMNESAGENT_S1_TOOL_GATE=1`:
  - Текст последнего сообщения пользователя и ассистента подается на вход вопросу `Choice` с категориями: `["filesystem", "shell", "memory", "web", "general"]`.
  - При выборе `"filesystem"` подсказываются `file_read, file_write, file_edit`; при `"shell"` — `shell`; при `"memory"` — `memory_store, memory_recall`.
  - Корректно распознаются русскоязычные интенты («удали ветку в гите», «сохрани в память пароль», «прочти файл»).

## 5. Сценарии Given / When / Then (включая деградацию)

### Сценарий 1: Штатная канальная классификация (P1 Happy Path)
- **Given**: Бот подключен к каналу Telegram, флаг `OMNESAGENT_S1_CHANNEL_INTENT=1`, веса Laya загружены в RAM.
- **When**: В канал поступает сообщение: «Ребята, кто завтра пойдет на митап?».
- **Then**:
  1. `omnesagent-s1` классифицирует интент как `NO_REPLY_INFO` с вероятностью $\ge 0.88$ за 28 мс.
  2. Сетевой вызов LLM **не выполняется** (0 потраченных токенов провайдера).
  3. Бот игнорирует реплику без генерации видимого ответа.
  4. Решение фиксируется в `data/s1/decisions.jsonl`.

### Сценарий 2: Отсутствие весов модели (Degradation: Missing Weights)
- **Given**: Переменная `OMNESAGENT_S1_PROVIDER=laya`, но каталог по пути `OMNESAGENT_S1_PATH` пуст, а интернет недоступен.
- **When**: Агент стартует и инициализирует `SystemOneProvider`.
- **Then**:
  1. Провайдер ловит ошибку загрузки safetensors, логирует предупреждение уровня `WARN` через `omnesagent_log`.
  2. Фабрика переключается на внутренний `NoOpSystemOne` (деградация в режим `off`).
  3. Метод `is_available()` возвращает `false`.
  4. Все модули (`channels`, `runtime`, `memory`) выполняют свои стандартные эвристики и вызовы. Никаких паник или сбоев в работе агента.

### Сценарий 3: Защита от OOM на VPS (Degradation: Low Memory)
- **Given**: Omnes Agent запущен на VPS с 1 vCPU и 1 ГБ свободной памяти. Флаг `OMNESAGENT_S1_PROVIDER=laya`.
- **When**: При попытке аллокации тензоров энкодера детектируется нехватка памяти либо ошибка распределения памяти.
- **Then**:
  1. Исключение перехватывается в модуле инициализации, модель немедленно выгружается.
  2. Выставляется флаг аварийного отключения `s1_disabled_oom = true`.
  3. Генерируется структурированный лог с событием `omnesagent_log::EventCategory::Hardware`.
  4. Процесс агента сохраняет работоспособность в базовом режиме.

### Сценарий 4: Таймаут CPU-инференса
- **Given**: Процессор перегружен фоновыми задачами компиляции, время ответа Laya превысило бюджет 150 мс.
- **When**: `tokio::time::timeout` прерывает ожидание `spawn_blocking`.
- **Then**:
  1. Вызов возвращает `Err(Timeout)`.
  2. Модуль-вызыватель отбрасывает S1-рекомендацию и продолжает выполнение по стандартной ветке кода.
  3. В метриках инкрементируется счетчик `omnesagent_s1_timeouts_total`.

### Сценарий 5: Попытка автоматизации опасного действия (Security Invariant)
- **Given**: Модель Laya выдала вероятность $P=0.99$ («Действие абсолютно необходимо») на команду `shell: rm -rf /`.
- **When**: Управление доходит до контура исполнения инструментов.
- **Then**:
  1. Вызов передается в `approval_gate::gate_tool_approval`.
  2. Вероятность Laya **не учитывается** как автоматическое разрешение.
  3. Пользователю выводится обязательный интерактивный запрос на подтверждение операции.

## 6. Архитектурное решение ADR-013

### Запись в реестр архитектурных решений
- **Номер**: **ADR-013** (продолжение нумерации после ADR-012 WASI HTTP use-time resolution).
- **Статус**: Принято (Accepted).
- **Дата**: 2026-09-20.
- **Контекст**: Агент тратит избыточные токены и время сетевого RTT на тривиальные дискретные решения (фильтрация сообщений чата, селекция памяти, эвристики инструментов). Требуется локальный детерминированный механизм быстрых решений без добавления внешних демонов и без нарушения автономности.
- **Решение**:
  1. Внедрить легковесную мультиязычную дискретную модель **Laya** (421M, ModernBERT + Decision Head) под лицензией Apache-2.0.
  2. Использовать локальный стек инференса на базе `candle-transformers 0.8` (уже имеющийся в воркспейсе через `omnesagent-kag`).
  3. Выделить функционал в изолированный крейт `crates/omnesagent-s1`.
  4. Предусмотреть раздельные дефолты окружения: на Desktop (PC) — включено при наличии ресурсов; на VPS — выключено по умолчанию для защиты RAM-бюджета.
  5. Ввести абсолютный запрет на обход `approval_gate` через выводы Laya.
- **Последствия**:
  - *Положительные*: Снижение p95 задержки на отсеве сообщений в каналах с 1200 мс до 30 мс; экономия до 40% токенов контекста при длинных сессиях за счет умной компакции; нулевые затраты на сеть при классификации.
  - *Отрицательные / Риски*: Потребление RAM (~450 МБ в q8, ~1.6 ГБ в fp32); дополнительное время компиляции при первом включении фичи.

## 8. Методика замеров и критерии включения дефолтов

### 8.1 Условия проведения экспериментов
1. **Изолированная машина**: замеры производятся на простаивающем оборудовании (idle CPU < 5%, отсутствие параллельных сборок и тяжелых процессов).
2. **Воспроизводимые трейсы**: замеры проводятся на зафиксированном датасете из 50 реальных сессий (golden session traces).
3. **Два профиля окружения**:
   - Профиль А (Рабочая станция / Desktop): x86_64, 16+ ГБ RAM, многоядерный CPU (Windows 11).
   - Профиль Б (VPS / Ограниченный): 1–2 vCPU, 1–2 ГБ RAM (Linux / Debian).

### 8.2 Измеряемые метрики
- **Канальная задержка (p95)**: время от поступления входящего кадра до принятия решения о необходимости ответа.
- **Потребление токенов LLM**: суммарное количество токенов на сессию.
- **Коэффициент сохранения полезного контекста**: процент ключевых фактов сессии, сохранившихся после компакции.
- **Прирост RSS (RAM Overhead)**: разница в занимаемой оперативной памяти процесса агента до и после загрузки S1.

### 8.3 Числовые критерии включения флагов по умолчанию (Go / No-Go Gates)

| Флаг / Модуль | Метрика успеха для включения (Default ON) | Критерий отката (Остается Default OFF) |
|---|---|---|
| **`OMNESAGENT_S1_CHANNEL_INTENT`** (P1) | p95 задержки $\le 100$ мс **И** точность совпадения с тяжелой LLM $\ge 96\%$ **И** экономия LLM-вызовов $\ge 80\%$ в чатах. | p95 $> 150$ мс **ИЛИ** ложные отказы от ответа на реальный вопрос $> 1.5\%$. |
| **`OMNESAGENT_S1_COMPACTION`** (P2) | Сокращение входных токенов на длинных сессиях $\ge 35\%$ без потери правильности ответов на контрольные вопросы сессии. | Ошибки выполнения задач агентом из-за потери контекста увеличиваются более чем на 1%. |
| **`OMNESAGENT_S1_MEMORY_RERANK`** (P3) | Recall@5 не падает (> -0.5% отн.) **И** MRR вырастает не менее чем на $+4\%$. | Рост времени подготовки контекста $> 80$ мс. |
| **RAM-профиль Desktop** | Прирост RSS в режиме q8 $\le 550$ МБ (в fp32 $\le 1.8$ ГБ). | Утечки памяти, рост RSS со временем сессии. |
| **RAM-профиль VPS** | **Всегда OFF по умолчанию**. Включение разрешено только вручную при наличии $\ge 1.2$ ГБ гарантированно свободной памяти. | Запас свободной памяти VPS $< 800$ МБ. |

| Риск | Вероятность | Влияние | Компенсирующие меры (Mitigation) |
|---|---|---|---|
| **Нехватка памяти на VPS (OOM)** | Высокая | Критическое | Жесткий запрет дефолтного включения на VPS. Использование q8/int8 квантования. Проверка свободного объема памяти через `sysinfo` перед инициализацией. |
| **Высокая задержка на медленных CPU** | Средняя | Среднее | Лимит входа `OMNESAGENT_S1_MAX_TOKENS = 512`. Жесткий таймаут 150 мс в `tokio::time::timeout`. Тихий fallback на исходные эвристики при таймауте. |
| **Различие структуры decision head в Laya** | Средняя | Высокое | Этап M2 предусматривает чтение конфигурации головы из `rl_agent_config.json`. При несовместимости формата safetensors — fallback на ONNX/ort рантайм как запасной путь (Gate M2). |
| **Галлюцинации вероятностей Laya на опасных действиях** | Средняя | Критическое | Архитектурный инвариант: вероятности Laya **никогда** не имеют права санкционировать деструктивные операции. Контур `approval_gate.rs` защищен от внешнего подавления. |
| **Рост объема файла логов `decisions.jsonl`** | Низкая | Низкое | Ротация логов по дням согласно существующей политике `OMNESAGENT_LOG_RETENTION_DAYS`. Запись sha256 хэшей состояний вместо тяжелых текстовых дампов. |

## 10. Открытые вопросы владельцу

Все вопросы содержат четкую рекомендацию архитектора:

1. **Вопрос**: Допустимо ли автоматическое скачивание весов Laya с Hugging Face при первом старте Desktop-версии, если они отсутствуют в кэше?  
   - *Рекомендация*: **Нет, по умолчанию не качать без подтверждения**. Добавить в настройки Desktop UI кнопку «Загрузить интеллектуальный System One слой (~450 МБ)», чтобы не вызывать неожиданного сетевого трафика и блокировок у пользователей с лимитированным интернетом.
2. **Вопрос**: Какую схему квантования принять за приоритетную для поставки весов (q8 vs int8 vs fp16)?  
   - *Рекомендация*: **q8 (8-битное квантование)** как золотую середину: потеря точности менее 0.8%, размер весов снижается с ~1.6 ГБ до ~460 МБ, инференс на AVX2/AVX-512 CPU работает быстрее.
3. **Вопрос**: Следует ли в будущем вынести инструмент прямого обращения к S1 в MCP-инструменты агента (по аналогии с 37-м инструментом `s1` в ob2h)?  
   - *Рекомендация*: **Да, запланировать в v1.1** как отдельный MCP-инструмент `system_one_decide`, позволяющий агенту в цикле рассуждений быстро взвешивать альтернативы без обращения к под-агентам. В текущую версию v1.0 не включать для фокусировки на внутренних горячих путях.
4. **Вопрос**: Нужно ли поддерживать CUDA-ускорение инференса Laya в Windows сборках Omnes Agent?  
   - *Рекомендация*: **Оставить CPU по умолчанию**. Включать Candle с фичей `cuda` только при сборке из исходников с явным флагом `--features candle-cuda`, так как распространение бинарников с cuDNN резко увеличивает размер дистрибутива (на 1.5+ ГБ).
