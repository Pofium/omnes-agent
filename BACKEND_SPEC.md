# BACKEND_SPEC.md — Архитектурная спецификация бэкенда OmnesAgent (Rust Workspace)

Настоящий документ определяет целевую архитектуру, структуру крейтов, принципы разделения ответственности, контракты данных, политики безопасности и подсистемы локального инференса бэкенда OmnesAgent.

---

## 1. Обзор архитектуры и принципы проектирования

Бэкенд OmnesAgent спроектирован как высокопроизводительный, модульный монорепозиторий на языке **Rust** (MSRV 1.80+ / 1.96+) с асинхронным рантаймом **Tokio**.

### Ключевые архитектурные принципы:
1. **Single Source of Truth:** Бэкенд является единственным владельцем состояния системы, выполнения команд ОС, хранения долговременной памяти и маршрутизации LLM.
2. **Zero Unhandled Panics:** Все пути выполнения в production-коде должны корректно распространять ошибки через `anyhow::Result` или типизированные ошибки доменных крейтов без паник.
3. **Безопасность и Human-in-the-Loop:** Ни одна потенциально деструктивная операция (модификация защищенных файлов, запуск команд с высоким риском, доступ к внешним сетям) не выполняется автоматически без прохождения через `approval_gate`.
4. **Graceful Degradation:** Отсутствие локальных весов нейросетей, сбои внешних API или перегрузка сети никогда не приводят к аварийной остановке системы.

## 2. Структура крейтов Rust Workspace

```
backend/
├── apps/
│   ├── omnesagent/                 # Основной бинарник автономного агента и CLI
│   ├── omnescode/                  # Инженерный кодинг-агент для работы с репозиториями
│   └── omnesrelay/                 # Сервис шлюза каналов и ретрансляции событий
└── crates/
    ├── omnesagent-api/             # Общие структуры данных, DTO, схемы событий
    ├── omnesagent-channels/        # Адаптеры мессенджеров (Telegram, Discord, Slack) и оркестратор
    ├── omnesagent-compression/     # Алгоритмы сжатия токенов, AST-сжатие, zstd, SQZ
    ├── omnesagent-config/          # Парсинг config.toml, валидация окружения, CLI-параметры
    ├── omnesagent-gateway/         # Axum REST & WebSocket HTTP-сервер, session management
    ├── omnesagent-kag/             # Knowledge-Augmented Generation: AST-парсеры, граф кода, PageRank
    ├── omnesagent-log/             # Структурированное асинхронное логирование и трейсинг
    ├── omnesagent-macros/          # Процедурные макросы генерации инструментов и событий
    ├── omnesagent-memory/          # Долговременная память, SQLite FTS5, векторный поиск
    ├── omnesagent-providers/       # Интеграция с внешними LLM (OpenAI, Anthropic, DeepSeek, Ollama)
    ├── omnesagent-runtime/         # Агентный цикл выполнения, контекст, память, семантический роутер
    ├── omnesagent-s1/              # Локальный нейро-слой System One (Laya / ModernBert 421M)
    ├── omnesagent-tools/           # Реестр инструментов, песочница, approval gate
    └── omnesagent-tls/             # Управление TLS-сертификатами и безопасными соединениями
```

## 3. Сетевой шлюз (`omnesagent-gateway`)

Шлюз обеспечивает взаимодействие с Flutter Desktop/Web клиентами по протоколам HTTP/1.1, HTTP/2 и WebSocket.

### 3.1. Service Discovery
При запуске шлюз автоматически связывается с адресом `127.0.0.1:0` (динамический порт, если порт по умолчанию 42617 занят) и атомарно записывает файл дескриптора в `.omnes/gateway.json`:
```json
{
  "pid": 12840,
  "port": 42617,
  "host": "127.0.0.1",
  "started_at": "2026-09-20T22:30:00Z"
}
```

### 3.2. REST API Маршруты
- `GET /health` / `GET /api/health` — проверка доступности шлюза.
- `GET /api/v1/sessions` — список активных и архивных сессий.
- `POST /api/v1/sessions` — создание новой сессии (с привязкой к проекту и ветке).
- `GET /api/v1/providers` — реестр доступных провайдеров моделей (облачные + локальные Ollama/LM Studio).
- `POST /api/v1/ast/reindex` — триггер фоновой переиндексации AST-графа кодовой базы.
- `GET /api/v1/s1/status` — текущий статус слоя System One (готовность весов, используемый провайдер).
- `POST /api/v1/s1/download` — команда на фоновую предзагрузку весов модели Laya.

### 3.3. WebSocket Диспетчер
Обрабатывает постоянное соединение клиента, транслируя:
- Потоковые чанки генерации ответа LLM (`agent_chunk`).
- Запросы подтверждения опасных действий через Human-in-the-Loop (`approval_request` / `approval_response`).
- События прерывания речи (`voice_barge_in`) для немедленной остановки TTS.
- Информационные метрики производительности и задержки (S1 Latency, Token Usage).

## 4. Локальный нейро-слой System One (`omnesagent-s1`)

Слой System One (S1) на базе модели **Laya** (`convaiinnovations/laya`, ModernBERT-large + Decision Head, 421M параметров) предназначен для сверхбыстрого выполнения атомарных оценочных решений без обращения к удаленным LLM.

### 4.1. Контракт данных
- **`Question`**:
  - `Choice`: выбор одной из категориальных опций (`id`, `prompt`, `options`).
  - `Score`: шкала оценки от 1 до N (`id`, `prompt`, `max_score`).
  - `Noul`: калиброванная семантическая вероятность истинности утверждения 0.0..1.0 (`id`, `prompt`).
- **`Answer`**:
  - Строго типизированный результат с валидированными аксессорами `noul_prob()`, `choice_selected()`, `score_level()`.

### 4.2. Провайдеры и автозагрузка весов
- **`NoOpSystemOne` (`provider: off`):** Выключен по умолчанию. Нулевые накладные расходы.
- **`FakeSystemOne` (`provider: fake`):** Детерминированные ответы для тестов.
- **`CandleLayaProvider` (`provider: candle`):**
  - Реализован на базе `candle-transformers 0.8` и `tokenizers 0.21`.
  - **Автоматическое разрешение весов:** При отсутствии локального пути `OMNESAGENT_S1_PATH` использует `hf-hub` для проверки стандартного кэша `~/.cache/huggingface/hub/`. Если файлы отсутствуют — автоматически скачивает `config.json`, `tokenizer.json`, `model.safetensors` (~800 МБ) с Hugging Face Hub.
  - **Head+Tail Truncation:** При превышении лимита токенов сохраняет начальный контекст и конец реплики.
  - **Изоляция в потоке:** Инференс выполняется в `tokio::task::spawn_blocking` с ограничением по тайм-ауту (`OMNESAGENT_S1_TIMEOUT_MS`, по умолчанию 150 мс).

### 4.3. Точки интеграции в рантайм:
1. **Быстрый Gate каналов (`omnesagent-channels`):** фильтрация спама и определение необходимости ответа в групповых чатах за ~30 мс.
2. **Семантическая компактификация (`omnesagent-runtime/agent/history_trim.rs`):** функция `trim_with_s1_scoring` оценивает ценность реплик диалога (1..5) по отношению к цели и удаляет низкоприоритетные витки для экономии токенов.
3. **Rerank памяти (`omnesagent-runtime/agent/memory_inject.rs`):** фильтрация кандидатов долговременной памяти по калиброванной Noul-вероятности (порог 0.40).
4. **Шлюз инструментов (`omnesagent-runtime/agent/context_analyzer.rs`):** мультиязычная подсказка требуемых категорий инструментов.
5. **Семантический роутер (`omnesagent-runtime/agent/classifier.rs`):** классификация запросов пользователей по профилям `fast`, `code`, `reasoning`.

## 5. Граф знаний кода и KAG (`omnesagent-kag`)

Обеспечивает глубокое структурное понимание кодовой базы проекта без расхода токенов внешних LLM.

- **AST-парсеры:** Поддержка 10 языков (Rust, Python, TypeScript/JavaScript, Go, Dart/Flutter, PHP, Java, SQL, C/C++). Извлечение символов (`fn`, `struct`, `class`, `trait`, `interface`) и ребер (`CALLS`, `IMPORTS`, `DEFINES`, `INHERITS`).
- **Графовая аналитика:**
  - Расчет **PageRank** для выявления ключевых архитектурных узлов (**God Nodes**).
  - Алгоритм Тарьяна (SCC) для поиска циклических зависимостей.
  - Метрики нестабильности компонентов ($I = C_e / (C_a + C_e)$).
  - Расчет **Blast Radius** (радиуса поражения) перед внесением правок в код с градацией риска `Low`, `Medium`, `High`.
- **Векторный движок:**
  - Встроенный Candle BERT MiniLM (`all-MiniLM-L6-v2`, 384 dim) на CPU.
  - Алгоритм ранжирования **Reciprocal Rank Fusion (RRF $k=60$)** для объединения полнотекстового поиска FTS5 и векторного сходства.

## 6. Память и хранилище (`omnesagent-memory`)

- **Хранилище:** Встроенная SQLite с FTS5 и поддержкой векторных блобов.
- **Временное затухание:** Экспоненциальное затухание релевантности старых воспоминаний (Half-life 30 дней).
- **Дедупликация:** MMR (Maximal Marginal Relevance) с коэффициентом $\lambda = 0.7$ для предотвращения дублирования однотипных фактов в системном промпте.
- **Изоляция сессий:** Разделение памяти на уровни `Global` (профиль и привычки пользователя), `Project` (архитектурные решения) и `Session` (краткосрочный диалоговый контекст).

## 7. Безопасность и Approval Gate (`omnesagent-tools`)

Все действия инструментов категоризируются по уровням риска:
- **Low (Read-only):** Чтение файлов, поиск по коду, проверка git status, HTTP GET запросы — выполняются автономно.
- **Medium (Idempotent Writes):** Редактирование локальных файлов в рамках проекта, создание временных скриптов — логируются с возможностью отката.
- **High (Destructive & System):** Выполнение shell-команд (`rm`, `git push --force`, запуск системных процессов, модификация системных файлов вне репозитория) — **обязательно блокируются** до получения явного подтверждения пользователя через `ApprovalRequestFrame`.
- **Правило защиты S1:** Никакие вероятностные выводы модели Laya не имеют права переопределять или обходить `approval_gate`.

## 8. Бэкенд-подсистема расширенной наблюдаемости, траекторий и диалогового UX

Для обеспечения требований фронтенда по адаптации возможностей **DeepSeek Harness** и оптимизации диалогового взаимодействия (устранение расхождений, структурирование CoT, трассировка) в бэкенде реализуются следующие подсистемы.

### 8.1. Потоковая диспетчеризация траекторий (Trajectory Streaming Engine)
- **Таблица `session_steps` в SQLite `sessions.db`:**
  ```sql
  CREATE TABLE IF NOT EXISTS session_steps (
      id TEXT PRIMARY KEY,
      session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
      turn_id TEXT NOT NULL,
      step_index INTEGER NOT NULL,
      parent_step_id TEXT,
      step_type TEXT NOT NULL, -- 's1_gate', 'context_inject', 'cot_thinking', 'tool_call', 'tool_observation', 'synthesis'
      payload_json TEXT NOT NULL,
      tokens_used INTEGER DEFAULT 0,
      duration_us INTEGER DEFAULT 0,
      created_at TEXT NOT NULL
  );
  CREATE INDEX IF NOT EXISTS idx_steps_session_turn ON session_steps(session_id, turn_id);
  ```
- **WebSocket фрейм `trajectory_step`:** шлюз отправляет атомарные события траектории клиенту в реальном времени, позволяя строить интерактивный граф исполнения шагов.

### 8.2. Движок ветвления сессий (Session Forking & Time Travel)
- **REST-эндпоинт `POST /api/v1/sessions/{id}/fork`:**
  - **Входные параметры:**
    ```json
    {
      "at_step_id": "step_abc123",
      "new_title": "Оптимизация (Ветка 2)",
      "overrides": {
        "model": "deepseek-r1",
        "system_prompt": "...",
        "mode": "deep_code"
      }
    }
    ```
  - **Логика бэкенда:** Атомарно создает новую сессию, копируя историю сообщений и шагов ровно до момента `at_step_id`. Состояние файлов и памяти изолируется в отдельную ветвь диалога.

### 8.3. Анализатор и профилировщик бюджета токенов (Context Budget Profiler)
В `omnesagent-runtime/src/agent/context_budget.rs` реализуется динамический замер токенов перед каждым вызовом LLM:
- Подсчет компонентов:
  - `system_tokens`: базовый системный промпт и схемы тулов.
  - `kag_ast_tokens`: внедренные фрагменты графа кода и сигнатуры.
  - `memory_tokens`: факты долговременной памяти после MMR-фильтрации.
  - `dialog_history_tokens`: сжатая история реплик.
  - `tool_outputs_tokens`: выводы завершенных инструментов текущего витка.
  - `compression_saved_tokens`: объем сэкономленных токенов благодаря `omnesagent-compression` (Zstandard / SQZ) и семантическому триммингу `omnesagent-s1`.
- Регулярная отправка фрейма `context_budget_update` на клиент.

### 8.4. Двухканальный стриминг рассуждений и цитирований (DeepSeek CoT & Grounding)
Для устранения расхождений в диалогах и разделения рассуждений от полезного ответа шлюз разделяет стриминг на специализированные фреймы:
- **`thinking_chunk`:** поток скрытых рассуждений модели (`<think>` CoT от DeepSeek-R1 / Claude Thinking), передаваемый в изолированный канал для отображения в сворачиваемом блоке.
- **`answer_chunk`:** основной полезный текст ответа.
- **`grounding_citation`:** структурированные ссылки на источники фактов (путь к файлу `repo/src/auth.rs#L40`, id узла AST-графа или ключ долговременной памяти). Клиент рендерит их как кликабельные интерактивные бейджи с номерами, исключая субъективные домыслы модели.

### 8.5. Профили операционных режимов (Execution Profiles Engine)
Рантайм поддерживает динамическое переключение профилей исполнения (`AgentExecutionMode`):
- **`Fast`:** приоритет локального S1 (Laya), жесткое сжатие контекста, легкие модели (DeepSeek-V3), температура 0.2.
- **`DeepCode`:** максимальная глубина KAG (3 уровня зависимостей), авто-запуск проверок компилятора (`cargo check`, `flutter analyze`).
- **`Architect`:** увеличенный бюджет CoT-рассуждений (DeepSeek-R1), двухфазная верификация, обязательная генерация артефактов планов.
- **`RalphLoop`:** автономный цикл до 10 итераций с автоматической проверкой тестов и откатом изменений при регрессии.

### 8.6. Экспорт и воспроизведение трасс (Trace Replay & Eval API)
- **`GET /api/v1/sessions/{id}/export_trace`:** выгрузка сессии в стандартизированный формат JSONL (по стандарту `omnesagent-eval`), содержащий точные системные промпты, входные данные, вызовы инструментов и вердикты.
- **`POST /api/v1/sessions/replay`:** запуск детерминированного воспроизведения трассы для оценки качества обновленных моделей и отладки регрессий.
