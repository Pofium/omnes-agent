# FRONTEND_SPEC.md — Архитектурная спецификация клиентской части OmnesAgent (Desktop & Web)

Настоящий документ определяет целевую архитектуру, структуру компонентов, протоколы сетевого взаимодействия, стандарты дизайн-системы и правила реализации клиентского приложения OmnesAgent.

---

## 1. Обзор и технологический стек

Клиентская часть OmnesAgent представляет собой кроссплатформенное рабочее место инженера и оператора автономных AI-агентов, поддерживающее режимы **Desktop (Windows x64 / macOS / Linux)** и **Web**.

- **Фреймворк:** Flutter 3.x (канал Stable) / Dart 3.x.
- **Архитектурный паттерн:** Clean Architecture + Reactive State Management на базе **GetX** (`GetxController`, `Rx`, `Obx`, `GetView`).
- **Сетевой протокол:**
  - **REST API:** `GatewayHttpClient` (HTTP/1.1 и HTTP/2) для конфигурирования, управления сессиями, профилями и метаданными.
  - **WebSocket:** `GatewayWsClient` для реактивного двунаправленного обмена фреймами в реальном времени (стриминг токенов, Human-in-the-loop Approvals, голосовой дуплекс, статусы инференса).
- **Дизайн-система:** `Cyber / reui` на базе кастомизированного `shadcn/ui` (Dark Slate / Neon Cyan & Violet акценты, строгие радиусы скругления, плотная компоновка инженерного IDE).

## 3. Протоколы взаимодействия со шлюзом (Single Source of Truth)

Фронтенд **никогда не выполняет прямого доступа к файловой системе ОС или терминалу** для выполнения агентных действий. Единственным владельцем состояния и среды исполнения является локальный Rust-шлюз `omnesagent-gateway`.

- [ ] **Дерево проекта и содержимое файлов — только через шлюз.** Ни `dart:io`, ни `universal_io`: дерево — `GET /api/v1/editor/tree`, содержимое и запись — `GET|PUT /api/v1/editor/file`, редактирование — канал `/ws/editor/{buffer_id}` (§3.3, §5.5). Прямое чтение файла (`task_workspace_controller.dart::openProjectFile`) и обход каталогов (`desktop_sidebar.dart`) — существующий техдолг, подлежащий удалению вместе с внедрением редактора (BACKEND_SPEC §9.1).

### 3.1. Динамическое обнаружение шлюза (Service Discovery)
- [x] Проверка файла дескриптора шлюза `.omnes/gateway.json` в рабочей директории:
   ```json
   {
     "pid": 12840,
     "port": 42617,
     "host": "127.0.0.1",
     "auth_token": "..."
   }
   ```
- [x] Переменные окружения: `OMNES_GATEWAY_URL` или `OMNES_GATEWAY_PORT`.
- [x] Fallback: `http://127.0.0.1:42617`.

### 3.3. Канал редактора `/ws/editor/{buffer_id}` (`EditorWsClient`)

Отдельное WebSocket-соединение на каждый открытый буфер (файл). Шлюз — источник событий, клиент — источник правок. Полная спецификация ядра — BACKEND_SPEC §9, фреймы:

| Тип фрейма (`type`) | Направление | Назначение | Статус |
|---|---|---|---|
| `hello` | S $\to$ C | Ревизии буфера и представления, язык, EOL/кодировка, `read_only`, таблица стилей, настройки редактора. | [x] Ф0 |
| `rows_snapshot` | S $\to$ C | Диапазон display-строк: `row`, `buffer_row`, `kind` (text/fold/block/spacer), `text`, `runs` (длина + id стиля), `inlays`, `fold`, `indent_guide_cols`, `selections`. | [x] Ф0* |
| `rows_changed` | S $\to$ C | Дельта: инвалидированные строки после правки (`start_line`, `inval_count`, `new_count`). | [x] Ф0 |
| `edit_ops` | C $\to$ S | Правки пользователя (`base_rev`, диапазоны + текст, группа) — уже применённые оптимистично локально. | [x] Ф0 |
| `edit_ack` | S $\to$ C | Подтверждение правки или корректировка (`adjusted_ops`) при рассинхронизации ревизий. | [x] Ф0* |
| `remote_ops` | S $\to$ C | Правки других реплик (агент, второе окно) с автором — никогда не попадают в локальный undo-стек. | [ ] Ф7 |
| `cursor` / `selection` | C $\to$ S | Позиции курсоров и выделений (якоря). | [ ] Ф7 |
| `presence` | S $\to$ C | Где работает агент (диапазон, метка сессии) для режима «следовать за агентом». | [ ] |
| `folds` | C $\to$ S | Свернуть/развернуть диапазон, «свернуть всё». | [ ] |
| `diagnostics` | S $\to$ C | Диагностики файла (severity, диапазоны в UTF-16, source). | [ ] |
| `lsp_request` / `lsp_response` | C $\leftrightarrow$ S | Запросы LSP-фич: completion (+resolve), hover, definition/declaration/references, code_action, signature_help, format, inlay_hints, semantic_tokens, document_symbols. | [ ] |
| `server_status` / `work_done_progress` | S $\to$ C | Состояние языковых серверов и прогресс длительных операций. | [ ] |
| `agent_proposal` / `agent_proposal_result` | S $\leftrightarrow$ C | Предложение правок агента (ханки) и решение пользователя (принять/отклонить по ханку/файлу/всему). | [ ] |
| `save_state` | S $\to$ C | Грязный флаг, факт сохранения, дрейф файла на диске (конфликт внешней правки). | [x] Ф0* |
| `show_message` / `log_message` | S $\to$ C | Сообщения языковых серверов, требующие отображения в UI. | [ ] |
| `error` | S $\to$ C | Ошибка с кодом и контекстом. | [x] Ф0 |

Статус Ф0 (27.09.2026): реализованы фреймы `hello`, `rows_snapshot`, `rows_changed`, `edit_ops`, `edit_ack`, `save_state`, `error` — крейт `omnesagent-editor` + `omnesagent-gateway/src/ws_editor.rs`, транспорт `frontend/shared/lib/core/gateway/editor_ws.dart`, DTO `model/editor/editor_frames.dart`. Пометка `Ф0*` — фрейм работает, но с усечённой нагрузкой: `rows_snapshot` без `runs`/`inlays`/`fold` (Ф1), `edit_ack` без `adjusted_ops` (Ф7), `save_state` без дрейфа диска (Ф3).

Инварианты на стороне клиента:
1. Фрейм с базовой ревизией, не совпадающей с локальной, **не применяется** — клиент запрашивает `rows_snapshot` для нужного диапазона (идемпотентное восстановление).
2. Оптимистичная правка всегда несёт `base_rev`; при `edit_ack` с корректировкой локальное состояние пересобирается из ответа шлюза.
3. Правки других реплик не смешиваются с локальным undo/redo.
4. Клиент не выполняет парсинг/подсветку: `runs` — готовые индексы стилей из общей таблицы.

### 5.5. Редактор файлов в правой панели (File Editor)

Вкладка `editor` в `DesktopInspectorPanel` — полноценный редактор кода (заменяет существующий read-only просмотрщик вкладки `file`: `inspector_panel.dart::_buildFileViewerTab`, где содержимое рисуется `SelectableText` целиком, а номера строк — виджетами в `Column`). Модель текста живёт в шлюзе (BACKEND_SPEC §9), клиент — виртуальный вьюпорт.

**Состав модуля** (`frontend/desktop/lib/features/inspector/editor/`):

- [x] `editor_controller.dart` — состояние вьюпорта буфера: видимый диапазон display-строк, кэш строк, курсоры/выделения, undo-стек локальных правок, грязный флаг; подписка на канал через `EditorWsClient`. *(Ф0: одиночный курсор, undo только своих правок; мультикурсор — Ф2.)*
- [x] `editor_client.dart` — обёртка над `/ws/editor/{buffer_id}`: подписка, отправка `edit_ops`/`cursor`/`selection`/`folds`, буферизация при реконнекте, запрос `rows_snapshot` при рассинхронизации. *(Ф0: `edit_ops` + resync + REST-fallback сохранения; `folds` — Ф1.)*
- [x] `editor_viewport.dart` — виртуализированный вьюпорт на `CustomPaint` + `TextInputClient`: рисуются только видимые строки, шейпинг строк кэшируется (`Paragraph`/`TextPainter` на layout-строку), `RepaintBoundary` на вьюпорт, горизонтальный и вертикальный скролл, курсор с мерцанием, drag-выделение, хит-тест позиции. *(Ф0: моноширинный слой, колесо/скроллбар, IME-ввод через дифф текущей строки. Ф1: покраска `runs` — сегменты `TextSpan` по таблице стилей из `hello.styles`, цвета/жирность/курсив из общей темы шлюза; фолды/инлайны — дальше по фазе.)*
- [x] `editor_gutter.dart` — номера строк (абсолютные/относительные), маркеры git-диффа, маркеры диагностик и правок агента, индикаторы фолдов. *(Ф0: только абсолютные номера; маркеры/фолды — Ф1/Ф4.)*
- [ ] `find_replace_bar.dart` — поиск/замена в файле (regex, case, whole word, «заменить все»), результаты как подсветка диапазонов; кнопки «предыдущее/следующее». *(Ф6.)*
- [ ] `completion_menu.dart`, `hover_popover.dart`, `signature_help.dart` — LSP-UI поверх вьюпорта с привязкой к позиции курсора.

## 6. Безопасность и стабильность

- [x] **Защита от сбоев сети:** При обрыве WebSocket-соединения клиент автоматически производит экспоненциальный переподключение (1s, 2s, 4s, макс. 10s) с сохранением состояния ввода.
- [x] **Изоляция пользовательских данных:** Чувствительные API-ключи никогда не отображаются в открытом виде в логах или UI; хранятся в защищенном локальном хранилище или `~/.omnesagent/config.toml`.
- [x] **Никаких блокировок UI-потока:** Все тяжелые вычисления, парсинг JSON больших деревьев и диффов выносятся во Flutter `compute()` изоляты.
- [x] **Согласование версий редактора:** оптимистичные правки вьюпорта всегда подтверждаются ревизией шлюза (`edit_ack`); при рассинхронизации клиент восстанавливается идемпотентным `rows_snapshot` по диапазону, без перезагрузки буфера и без потери несохранённых изменений. *(Ф0: rev-гейтинг на шлюзе, несохранённые правки живут в буфере шлюза; rebasing через `adjusted_ops` — Ф7.)*
- [ ] **Устойчивость канала редактора:** при обрыве `/ws/editor/{buffer_id}` ввод блокируется с явной индикацией (правки не теряются, не уходят «в никуда»), при переподключении состояние пересобирается из `hello` + `rows_snapshot`; сам текст буфера не теряется, так как хранится в шлюзе. *(Ф0 частично: авто-реконнект есть, состояние пересобирается из `hello` + `rows_snapshot`, статус канала в строке статуса; блокировка ввода при обрыве — Ф3.)*
- [ ] **Границы доверия:** клиент не доверяет своему кэшу как источнику истины — источник истины всегда шлюз; любые правки, приходящие от агента, отображаются явно (предложение/присутствие), а не применяются молча.

## 7. Дорожная карта развития UI/UX: адаптация концепций DeepSeek Harness

На основе сравнительного анализа архитектуры и пользовательского опыта открытого фреймворка **DeepSeek Harness (`deepseek-ai/deepseek-harness`)** определен спектр критических возможностей для углубленной наблюдаемости (Observability), ветвления исполнения (Time Travel) и интерактивного профилирования агента в OmnesAgent ADE.

### 7.1. Интерактивная траектория агента (Trajectory Timeline & Step Inspector)
*Концепт DeepSeek Harness:* В отличие от классического плоского чата, DeepSeek Harness предоставляет сквозную структуру «Trajectory» — строго упорядоченную, разворачиваемую ленту каждого микро-действия агента.

**Целевая реализация в OmnesAgent (`trajectory_inspector_panel.dart`):**
- [x] **Иерархическая шкала шагов (Execution Graph):**
  - Пользовательский интент $\to$
  - Решение локального S1 Gate (оценка намерений/инструментов за 25 мс) $\to$
  - Инъекция KAG-контекста и памяти (BM25 + RRF + векторный скор) $\to$
  - Скрытая цепочка рассуждений (CoT / Thinking stream) $\to$
  - Вызов инструмента (Tool Call) с диффом состояния и таймингом $\to$
  - Ответ инструмента (Observation) $\to$
  - Финальный синтез ответа.
- [x] **Инспектор отдельного шага (Step Drawer):**
  - Раскрытие точных входных аргументов, необработанного вывода, затраченных миллисекунд и потребленных токенов для любого шага.
  - Позволяет мгновенно диагностировать «галлюцинации» или ошибки в аргументах инструментов без копания в терминальных логах.

### 7.2. Путешествие во времени, ветвление сессий и модернизация Сайд-чата (Side Chat Upgrade)
*Концепт DeepSeek Harness:* Возможность возобновления, ветвления и изолированного уточнения контекста из произвольной зафиксированной точки истории.

**Целевая реализация в OmnesAgent — эволюция существующего `Side Chat` (`inspector_panel.dart` $\to$ вкладка `side_chat` / `SideChatController`):**
Вместо создания дублирующих всплывающих окон функционал развилок и уточнений интегрируется **напрямую в уже существующую правую панель инспектора (вкладка «Сайд-чат»)**.

- [x] **Активация контекстного режима Сайд-чата:**
  - При клике на кнопку «Уточнить» или «Разветвить» у любого сообщения, шага или фрагмента ответа в основном чате:
    - Правая панель `InspectorPanel` автоматически распахивается (если была скрыта) и переключается на вкладку `side_chat`.
    - Контроллер `SideChatController` переводится из общего режима быстрых вопросов (`/btw`) в режим привязанного контекстного треда (`Thread Context Mode`).
- [x] **Карточка родительского контекста в Сайд-чате (`Parent Context Header`):**
  - **Краткое изложение сути (TL;DR Summary):** В самом верху панели сайд-чата закрепляется компактная плашка с кратким изложением сути вопроса или ключевого тезиса ответа, к которому привязана развилка.
  - **Интерактивная ссылка-якорь на родительский ответ (`Anchor Link`):** Кликабельный бейдж `[🔗 К исходному ответу]`. При нажатии на него левое основное окно плавно скроллится к родительскому сообщению и подсвечивает его пульсирующей неоновой рамкой на 1.5 секунды.
  - **Контекстная цитата выделения (Quote Snippet):** Если пользователь выделил конкретный абзац или строку кода в основном чате перед нажатием «Уточнить», в шапку сайд-чата автоматически подставляется форматированная цитата `«...»`.
- [x] **Изоляция и слияние результатов (Sub-thread Merge & Promote):**
  - В сайд-чате пользователь ведет точечный диалог с агентом без риска засорить или сломать основной контекст задачи.
  - Кнопка **«Применить в основной диалог» (Merge / Promote to Main):** позволяет в один клик перенести выработанное в сайд-чате решение или скорректированный код обратно в основной поток в виде подтвержденного резюме.
- [x] **Визуальное дерево ветвления сессий (Session Graph View):**
  - Дерево родительских сессий и развилок отображается в боковом меню по аналогии с графом веток Git.

### 7.3. Профилировщик контекста и токеномики (Tokenomics & Context Flamegraph)
*Концепт DeepSeek Harness:* Прозрачная детализация того, чем именно заполнено контекстное окно модели на каждом шаге.

**Целевая реализация в OmnesAgent:**
- [x] **Горизонтальный составной стек-бар контекстного окна (`ContextBudgetBar`):**
  - `[Системный промпт (X%)]` | `[KAG AST Граф (Y%)]` | `[Память (Z%)]` | `[История чата (W%)]` | `[Выводы инструментов (V%)]` | `[Свободно (K%)]`.
- [x] **Счетчик компрессии и экономии (Savings Counter):**
  - Отображение в реальном времени сэкономленных токенов и затрат благодаря встроенному Rust-модулю компрессии `omnesagent-compression` (Zstandard, AST compacting) и семантическому триммингу `omnesagent-s1`.
  - Метрика «Экономия средств ($) и токенов (%) за сессию».

### 7.4. Инспектор границ песочницы (Sandbox Perimeter Inspector)
*Концепт DeepSeek Harness:* Наглядная верификация прав доступа и ограничений песочницы перед запуском автономных действий.

**Целевая реализация в OmnesAgent:**
- [x] Визуальный виджет в шапке задачи:

  - Статус сетевой песочницы (Online / Local Only / Whitelist domains).
  - Уровень автономии тулов: `ReadOnly`, `AutoApproveIdempotent`, `StrictHumanInTheLoop`.

### 7.5. Быстрый переключатель операционных режимов (Agent Mode Switcher)
*Концепт DeepSeek Harness:* Предустановленные режимы работы под тип задачи (Standard, Minimal, Creator).

**Целевая реализация в OmnesAgent (чипы в панели ввода):**
- [x] ⚡ **Speed / Fast Mode:** Приоритет локального слоя S1 (Laya) + быстрые легковесные модели, сжатый контекст, мгновенный ответ.
- [x] 💻 **Deep Code Mode:** Включение глубокого KAG-графа кода, AST-валидатора, автопрогона линтеров и тестов компилятора (`cargo test`, `flutter test`).
- [x] 🧠 **Architect / CoT Mode:** Максимальный бюджет reasoning-токенов, структурированные артефакты планов, двухфазная верификация изменений.
- [x] 🔁 **Autonomous Ralph Loop:** Запуск автономного мульти-итеративного цикла решения сложных инженерных задач с фиксацией вердиктов и автооткатом при регрессиях.

### 7.6. Экспорт и воспроизведение трасс (Trace Export & Replay Harness)

- [x] Возможность загрузки трассы для детерминированного воспроизведения через `/api/v1/sessions/replay`.

### 7.7. Оптимизация диалогового UX и устранение расхождений (DeepSeek Dialog Best Practices)
Сравнение с диалоговым UX DeepSeek выявило ключевые причины субъективных «расхождений» и информационного шума в текущих диалогах: смешивание скрытых рассуждений с ответом, простыни логов терминала и отсутствие прозрачных источников фактов.

**Целевые улучшения UX диалогов в OmnesAgent:**
1. [x] **Изолированный аккордеон размышлений (`ThinkingAccordion` / «DeepThink / Ход мыслей»):**
   - Стриминг CoT-токенов (`thinking_chunk`) рендерится в специальном виджете `ThinkingAccordion` с таймером («Рассуждал 14 сек»), приглушенной моноширинной типографикой и плавной анимацией пульсации.
   - По умолчанию блок автоматически сворачивается после завершения генерации, оставляя чистый структурированный ответ и не перегружая экран.
2. [x] **Компактные карточки инструментов (Tool Cards Folding):**
   - Выводы компиляторов и команд на сотни строк автоматически сворачиваются в карточки с цветовым бейджем: `[✓ cargo check — 0 errors] [Показать лог 42 строки]`.
   - Полный вывод открывается по клику во всплывающем окне или встроенном превью с подсветкой синтаксиса.
3. [x] **Верифицируемые цитирования и граундинг (`GroundingCitationBadge`):**
   - Для устранения расхождений все факты, извлеченные из KAG-графа или долговременной памяти, снабжаются интерактивными сносками `[1]`, `[2]`.
   - При наведении отображается всплывающее превью точного файла (`file:///src/auth.rs#L40`) или формулировка сохраненного решения из `ob2h`, что исключает подозрения в галлюцинациях модели.
4. [x] **Мгновенная остановка и редактирование витка (Stop & Edit-to-Fork):**
   - Кнопка немедленной остановки генерации (`Stop`, реакция < 50 мс).
   - Кнопка «Редактировать» у каждого запроса пользователя: мгновенный переход к редактированию промпта с автоматическим созданием новой чистой ветки диалога.
5. [x] **Сплит-экран для артефактов (Side-by-Side Artifacts Canvas):**
   - Спецификации, таблицы, архитектурные планы и диаграммы Mermaid открываются в правой половине экрана (Canvas), а в ленте чата остается лишь компактный чип-ссылка `[📄 ARCHITECTURE.md (v2)]`.
