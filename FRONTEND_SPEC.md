# FRONTEND_SPEC.md — Архитектурная спецификация клиентской части OmnesAgent (Desktop & Web)

Настоящий документ определяет целевую архитектуру, структуру компонентов, протоколы сетевого взаимодействия, стандарты дизайн-системы и правила реализации клиентского приложения OmnesAgent.

---

## 1. Обзор и технологический стек

Клиентская часть OmnesAgent представляет собой кроссплатформенное рабочее место инженера и оператора автономных AI-агентов, поддерживающее режимы **Desktop (Windows x64 / macOS / Linux)** и **Web**.

- **Фреймворк:** Flutter 3.x (канал Stable) / Dart 3.x.
- **Архитектурный паттерн:** Clean Architecture + Reactive State Management на базе **GetX** (`GetxController`, `Rx`, `Obx`, `GetView`).
- **Сетевой протокол:**
  - **REST API:** `GatewayHttpClient` (HTTP/1.1 и HTTP/2) для конфигурирования, управления сессиями, профилями и метаданными.
  - **WebSocket:** `GatewayWsClient` для реактивного двунаправленного обмена фреймами в реальном времени (стриминг токенов, Human-in-the-loop Approvals, голосовой дуплекс, статусы инференса).
- **Дизайн-система:** `Cyber / reui` на базе кастомизированного `shadcn/ui` (Dark Slate / Neon Cyan & Violet акценты, строгие радиусы скругления, плотная компоновка инженерного IDE).

│   │   ├── design_system/          # Атомарные UI-компоненты: кнопки, инпуты, бейджи, поповеры, диалоги

│   │   ├── features/
│   │   │   ├── workspace/          # Task Workspace: task_workspace_controller.dart, task_workspace_view.dart
│   │   │   ├── settings/           # desktop_settings_dialog.dart
│   │   │   ├── automations/        # automations_view.dart, keep-awake, cron
│   │   │   └── sop/                # sop_studio_view.dart, sop_studio_controller.dart

## 3. Протоколы взаимодействия со шлюзом (Single Source of Truth)

Фронтенд **никогда не выполняет прямого доступа к файловой системе ОС или терминалу** для выполнения агентных действий. Единственным владельцем состояния и среды исполнения является локальный Rust-шлюз `omnesagent-gateway`.

### 3.1. Динамическое обнаружение шлюза (Service Discovery)
Клиент не завязывается на статические порты (42617/18789). Алгоритм резолва адреса:
1. Проверка файла дескриптора шлюза `.omnes/gateway.json` в рабочей директории:
   ```json
   {
     "pid": 12840,
     "port": 42617,
     "host": "127.0.0.1",
     "auth_token": "..."
   }
   ```
2. Переменные окружения: `OMNES_GATEWAY_URL` или `OMNES_GATEWAY_PORT`.
3. Fallback: `http://127.0.0.1:42617`.

### 3.2. WebSocket протокол фреймов (`GatewayWsClient`)
Обмен происходит в формате JSON-фреймов `GatewayFrame`:

| Тип фрейма (`type`) | Направление | Описание |
|---|---|---|
| `session_init` | C $\to$ S | Инициализация и подписка на события сессии (`session_id`). |
| `user_message` | C $\to$ S | Отправка реплики пользователя с прикрепленными контекстами. |
| `agent_chunk` | S $\to$ C | Стриминг токенов ответа модели (`delta`, `is_final`). |
| `tool_call_start` | S $\to$ C | Оповещение о вызове инструмента (`tool_name`, `arguments`). |
| `tool_call_end` | S $\to$ C | Результат выполнения инструмента (`stdout`, `stderr`, `code`). |
| `approval_request` | S $\to$ C | Запрос подтверждения рискованного действия (`action_type`, `risk_level`, `command`, `timeout_sec`). |
| `approval_response` | C $\to$ S | Решение пользователя: `approved: true/false`. |
| `voice_barge_in` | C $\to$ S | Прерывание голоса агента пользователем (немедленный сброс буфера TTS). |
| `s1_event` | S $\to$ C | Системные события слоя S1 (статус локального инференса, прогресс загрузки весов). |

4. **System One (Laya) — Локальный нейро-слой:**
   - Переключатель провайдера: `Выключен` / `Candle (Локальный)` / `Fake (Тестовый)`.
   - **Карточка автозагрузки:**
     - Автоскачивание модели `convaiinnovations/laya` (ModernBERT-large 421M, ~800 МБ) с Hugging Face Hub при первом включении.
     - Индикатор статуса: `Не загружена` $\to$ `Скачивание (XX%)` $\to$ `Готова (Локально)`.

     - `Компактификация истории` (семантический trim нерелевантных реплик).

## 6. Безопасность и стабильность

1. **Защита от сбоев сети:** При обрыве WebSocket-соединения клиент автоматически производит экспоненциальный переподключение (1s, 2s, 4s, макс. 10s) с сохранением состояния ввода.
2. **Изоляция пользовательских данных:** Чувствительные API-ключи никогда не отображаются в открытом виде в логах или UI; хранятся в защищенном локальном хранилище или `~/.omnesagent/config.toml`.
3. **Никаких блокировок UI-потока:** Все тяжелые вычисления, парсинг JSON больших деревьев и диффов выносятся во Flutter `compute()` изоляты.

## 7. Дорожная карта развития UI/UX: адаптация концепций DeepSeek Harness

На основе сравнительного анализа архитектуры и пользовательского опыта открытого фреймворка **DeepSeek Harness (`deepseek-ai/deepseek-harness`)** определен спектр критических возможностей для углубленной наблюдаемости (Observability), ветвления исполнения (Time Travel) и интерактивного профилирования агента в OmnesAgent ADE.

### 7.1. Интерактивная траектория агента (Trajectory Timeline & Step Inspector)
*Концепт DeepSeek Harness:* В отличие от классического плоского чата, DeepSeek Harness предоставляет сквозную структуру «Trajectory» — строго упорядоченную, разворачиваемую ленту каждого микро-действия агента.

**Целевая реализация в OmnesAgent (`trajectory_inspector_panel.dart`):**
- **Иерархическая шкала шагов (Execution Graph):**
  - Пользовательский интент $\to$
  - Решение локального S1 Gate (оценка намерений/инструментов за 25 мс) $\to$
  - Инъекция KAG-контекста и памяти (BM25 + RRF + векторный скор) $\to$
  - Скрытая цепочка рассуждений (CoT / Thinking stream) $\to$
  - Вызов инструмента (Tool Call) с диффом состояния и таймингом $\to$
  - Ответ инструмента (Observation) $\to$
  - Финальный синтез ответа.
- **Инспектор отдельного шага (Step Drawer):**
  - Раскрытие точных входных аргументов, необработанного вывода, затраченных миллисекунд и потребленных токенов для любого шага.
  - Позволяет мгновенно диагностировать «галлюцинации» или ошибки в аргументах инструментов без копания в терминальных логах.

### 7.2. Путешествие во времени, ветвление сессий и боковой диалог уточнений (Session Forking & Side-Thread Drawer)
*Концепт DeepSeek Harness:* Возможность возобновления, ветвления и изолированного уточнения контекста из произвольной зафиксированной точки истории.

**Целевая реализация в OmnesAgent (`fork_thread_drawer.dart`):**
- **Правое диалоговое окно развилки/уточнения (Split-View Side Dialog):**
  - При клике на кнопку «Уточнить» или «Разветвить» у конкретного сообщения или фрагмента ответа основная рабочая область делится на сплит-экран: слева остается основной диалог, а справа открывается панель локального контекстного треда.
- **Карточка родительского контекста в правом окне (`Parent Context Header`):**
  - **Краткое изложение сути (TL;DR Summary):** В самом верху правого окна отображается компактный блок с кратким изложением вопроса или тезиса ответа, к которому привязана развилка (формируется локальным слоем S1 Laya за 15 мс либо выжимкой первых 200 символов исходной реплики).
  - **Интерактивная ссылка-якорь на родительский ответ (`Anchor Link`):** Кликабельный бейдж `[🔗 К исходному ответу #Step-14]`. При нажатии на него левое основное окно плавно скроллится к родительскому сообщению и подсвечивает его пульсирующей неоновой рамкой на 1.5 секунды.
  - **Контекстная цитата выделения (Quote Snippet):** Если пользователь выделил конкретный абзац или строку кода в основном чате перед нажатием «Уточнить», в шапку правого окна автоматически подставляется форматированная цитата `«...»`.
- **Изоляция и слияние результатов (Sub-thread Merge & Promote):**
  - В правом диалоге пользователь может задавать точечные наводящие вопросы, запрашивать альтернативные варианты реализации или отлаживать гипотезу, не засоряя контекст основного конвейера.
  - Кнопка **«Применить в основной диалог» (Merge / Promote to Main):** позволяет в один клик перенести выработанное в боковом окне решение или скорректированный код обратно в основной поток в виде подтвержденного резюме.
- **Визуальное дерево ветвления сессий (Session Graph View):**
  - Дерево родительских и дочерних сессий отображается в сайдбаре по аналогии с графом веток Git.

### 7.3. Профилировщик контекста и токеномики (Tokenomics & Context Flamegraph)
*Концепт DeepSeek Harness:* Прозрачная детализация того, чем именно заполнено контекстное окно модели на каждом шаге.

**Целевая реализация в OmnesAgent:**
- **Горизонтальный составной стек-бар контекстного окна:**
  - `[Системный промпт (X%)]` | `[KAG AST Граф (Y%)]` | `[Память (Z%)]` | `[История чата (W%)]` | `[Выводы инструментов (V%)]` | `[Свободно (K%)]`.
- **Счетчик компрессии и экономии (Savings Counter):**
  - Отображение в реальном времени сэкономленных токенов и затрат благодаря встроенному Rust-модулю компрессии `omnesagent-compression` (Zstandard, AST compacting) и семантическому триммингу `omnesagent-s1`.
  - Метрика «Экономия средств ($) и токенов (%) за сессию».

### 7.4. Инспектор границ песочницы (Sandbox Perimeter Inspector)
*Концепт DeepSeek Harness:* Наглядная верификация прав доступа и ограничений песочницы перед запуском автономных действий.

**Целевая реализация в OmnesAgent:**
- Визуальный виджет в шапке задачи:
  - Разрешенный корень проекта (`workspace_root`).
  - Защищенные системные каталоги (блокировка `C:\Windows`, `~/.ssh`, `~/.gnupg`).
  - Статус сетевой песочницы (Online / Local Only / Whitelist domains).
  - Уровень автономии тулов: `ReadOnly`, `AutoApproveIdempotent`, `StrictHumanInTheLoop`.

### 7.5. Быстрый переключатель операционных режимов (Agent Mode Switcher)
*Концепт DeepSeek Harness:* Предустановленные режимы работы под тип задачи (Standard, Minimal, Creator).

**Целевая реализация в OmnesAgent (чипы в панели ввода):**
- ⚡ **Speed / Fast Mode:** Приоритет локального слоя S1 (Laya) + быстрые легковесные модели, сжатый контекст, мгновенный ответ.
- 💻 **Deep Code Mode:** Включение глубокого KAG-графа кода, AST-валидатора, автопрогона линтеров и тестов компилятора (`cargo test`, `flutter test`).
- 🧠 **Architect / CoT Mode:** Максимальный бюджет reasoning-токенов, структурированные артефакты планов, двухфазная верификация изменений.
- 🔁 **Autonomous Ralph Loop:** Запуск автономного мульти-итеративного цикла решения сложных инженерных задач с фиксацией вердиктов и автооткатом при регрессиях.

### 7.6. Экспорт и воспроизведение трасс (Trace Export & Replay Harness)
- Кнопка «Экспорт траектории» в меню сессии: выгрузка стандартизированного JSONL-архива с полной трассировкой всех шагов, аргументов и решений.
- Возможность загрузки трассы для регрессионного тестирования бэкенда через `cargo test -p omnesagent-eval` (сравнение ответов разных моделей на идентичных вводных данных).

### 7.7. Оптимизация диалогового UX и устранение расхождений (DeepSeek Dialog Best Practices)
Сравнение с диалоговым UX DeepSeek выявило ключевые причины субъективных «расхождений» и информационного шума в текущих диалогах: смешивание скрытых рассуждений с ответом, простыни логов терминала и отсутствие прозрачных источников фактов.

**Целевые улучшения UX диалогов в OmnesAgent:**
1. **Изолированный аккордеон размышлений («DeepThink / Ход мыслей»):**
   - Стриминг CoT-токенов (`thinking_chunk`) рендерится в специальном виджете `ThinkingAccordion` с таймером («Рассуждал 14 сек»), приглушенной моноширинной типографикой и плавной анимацией пульсации.
   - По умолчанию блок автоматически сворачивается после завершения генерации, оставляя чистый структурированный ответ и не перегружая экран.
2. **Компактные карточки инструментов (Tool Cards Folding):**
   - Выводы компиляторов и команд на сотни строк автоматически сворачиваются в карточки с цветовым бейджем: `[✓ cargo check — 0 errors] [Показать лог 42 строки]`.
   - Полный вывод открывается по клику во всплывающем окне или встроенном превью с подсветкой синтаксиса.
3. **Верифицируемые цитирования и граундинг (Grounding Citation Badges):**
   - Для устранения расхождений все факты, извлеченные из KAG-графа или долговременной памяти, снабжаются интерактивными сносками `[1]`, `[2]`.
   - При наведении отображается всплывающее превью точного файла (`file:///src/auth.rs#L40`) или формулировка сохраненного решения из `ob2h`, что исключает подозрения в галлюцинациях модели.
4. **Мгновенная остановка и редактирование витка (Stop & Edit-to-Fork):**
   - Кнопка немедленной остановки генерации (`Stop`, реакция < 50 мс).
   - Кнопка «Редактировать» у каждого запроса пользователя: мгновенный переход к редактированию промпта с автоматическим созданием новой чистой ветки диалога.
